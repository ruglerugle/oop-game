インターフェース

できることの約束
🎯 ミッション
interface が何のためにあるか（親が1つでも、できることを複数付けられる）を説明できるようになろう。4種類の鳥や動物に「泳げる・飛べる」を正しく付け、確認クイズに全問正解すれば合格。
未達成
ねこ博士
動物園に、アヒル・ペンギン・ワシがやってきた。どれも鳥だから Bird を継承する。ここで「泳げる動物を全員集めて泳がせる」機能が欲しくなった。泳げるのは、アヒル・ペンギン、それから鳥ではないけれどカワウソやイルカもいる。
うさ美
Bird に swim() を書くと、ワシまで泳げることになってしまう。Animal に書くと、ネコも泳げることになる。
ねこ博士
そうなんだ。「泳げる」は、継承の親子とは関係なく、ばらばらの動物が持っている性質だ。そこで、「泳げるなら swim() を持っていること」という約束だけを書いたものを作る。これをインターフェースと呼ぶ。
interface Swimmer { void swim(); }   // 泳げる：swim() を持つ約束
interface Flyer   { void fly(); }    // 飛べる：fly() を持つ約束
class Duck extends Bird implements Swimmer, Flyer {
    public void swim() { … }
    public void fly()  { … }
}
 implements は「約束を果たす」。約束したメソッドを全部書かないとコンパイラが止める
うさ美
親クラスは1つしか持てないけれど、インターフェースはいくつでも付けられるんですね。
ねこ博士
そう。そして、インターフェースも型として使える。Swimmer s = new Duck(); と書けて、s.swim() が呼べる。泳げる動物を Swimmer[] の配列に集めれば、アヒルもペンギンもカワウソも、同じ s.swim() で泳がせられる。前のステージのポリモーフィズムが、親子関係を越えて使えるわけだ。
うさ美
そもそも、親クラスを2つ持てれば、インターフェースはいらないのでは？ Duck extends Bird, Swimmer、のように。
ねこ博士
親を複数持てることを多重継承と呼ぶ。C++ のようにできる言語もある。でも、困ることがあるんだ。親 A と親 B の両方に、中身の違う move() があったら、子で move() を呼んだときに、どちらを使う？
うさ美
決められません。A の move() を使うか、B の move() を使うか、どこかで決めないと……。両方の親がさらに同じ祖父母を持っていたら、もっとややこしくなりそうです。
ねこ博士
その形は、親子の線がひし形になるので「ひし形問題」と呼ばれている。Java は、この問題を避けるために、中身を受け継ぐ親は1つだけ、約束（インターフェース）はいくつでも、と決めた。約束には基本的に中身が無いので、ぶつかる心配が少ないんだ。
うさ美
「基本的に」というのは？
ねこ博士
Java 8 からは、インターフェースにも default を付けて、ふつうの中身を書けるようになった。だから、2つのインターフェースに同じ名前の default メソッドがあると、ぶつかることがある。そのときは、Java はコンパイルを止めて、子クラスで書き直す（オーバーライドする）ことを求める。ぶつかったら人間が決める、という決まりだ。
継承（extends）：中身を受け継ぐ。親は1つだけ。「〜の一種」（is-a） インターフェース（implements）：「これができる」という約束。いくつでも付けられる。「〜ができる」（can-do） インターフェースも型になる → 親子関係を越えて、同じ呼び方で扱える

確認クイズ

Q1. 「泳げる」を Animal クラスに swim() として書くと困る理由は？

正解！ 親に書くと全部の子が受け継ぐ。親子関係と関係なく持つ性質は、インターフェースで付け足す。

Q2. Java の決まりとして正しいのは？

正解！ 中身を受け継ぐ親を1つにすることで、多重継承の「どちらの中身を使うか」問題を避けている。

Q3. Swimmer s = new Penguin(); のように、インターフェースを型として使う良いところは？

正解！ ポリモーフィズムを、継承の親子関係を越えて使える。
