クラスとインスタンス

設計図と実物、コンストラクタ
🎯 ミッション
クラス・インスタンス・フィールド・メソッド・コンストラクタの意味を説明できるようになろう。犬のインスタンスを3匹作り、確認クイズに全問正解すれば合格。
未達成
ねこ博士
犬のポチとハチは、名前も年齢も違う。でも、どちらも「名前と年齢を持ち、ほえることができる」という同じ形をしている。その形を書いたものをクラスと呼ぶ。たい焼きの型のようなものだ。
うさ美
型からたい焼きを何個も焼けるように、クラスから犬を何匹も作れる、ということですか？
ねこ博士
そう。クラスから作った1つ1つの実物をインスタンス（実例）と呼ぶ。オブジェクトとほぼ同じ意味で使われる。クラスの中には、2種類のものを書く。
フィールド：インスタンスが持つデータ（例：String name; 名前、int age; 年齢）。String は文字の並び、int は整数 メソッド：インスタンスができること（例：void bark() ほえる）。void は「答えを返さない」という意味
ねこ博士
インスタンスを作るには new を使う。Dog d1 = new Dog("ポチ", 3); と書くと、メモリのヒープに新しい Dog の場所が用意され、その番地が変数 d1 に入る。
うさ美
ヒープ……『メモリのしくみクエスト』で、好きなときに借りる場所として出てきました。d1 はポインタのように番地を持っている、ということですか？
ねこ博士
そう考えていい。Java では「参照」と呼んで、番地そのものを直接いじることはできないけれど、中身は番地だ。そして new Dog("ポチ", 3) の () の中の値は、コンストラクタに渡される。コンストラクタは、インスタンスができた直後に1回だけ呼ばれる、準備のための特別なメソッドで、クラスと同じ名前で書く。
class Dog {
    String name;
    int age;
    Dog(String name, int age) {   // コンストラクタ（クラスと同じ名前）
        this.name = name;
        this.age = age;
    }
    void bark() { System.out.println(name + "：ワン！"); }
}
 System.out.println(…) は、かっこの中を画面に表示する命令
うさ美
コンストラクタの中の this.name = name; の this は何ですか？
ねこ博士
「いま作っている（または、いまメソッドを呼ばれている）インスタンス自身」のことだ。引数の name と、フィールドの name が同じ名前なので、フィールドのほうを this.name と書いて区別している。
うさ美
d1.bark() と d2.bark() は、同じ bark の命令なのに、ポチとハチで違う名前が出る。bark の中の name は、呼ばれたインスタンス自身の name、つまり this.name のことだから。
ねこ博士
そう。メソッドは「どのインスタンスに対して呼ぶか」とセットで動く。d1.bark() は「d1 に、ほえろと頼む」と読むといい。データと、それを使う処理が、インスタンスの中でひとまとまりになっているね。
クラス：設計図（フィールドとメソッドの形）。プログラムに1回書く インスタンス：new で作る実物。フィールドの値はインスタンスごとに別々 コンストラクタ：new したときに1回呼ばれ、フィールドに最初の値を入れる メソッドの呼び出し：d1.bark() ＝ d1 自身（this）のデータを使って、ほえる
うさ美
犬だけでなく、猫や鳥のクラスも作ると、また name や eat() を何度も書くことになりませんか？ STAGE1 のコピーの問題が残っています。
ねこ博士
その通り。それを解くのが次の継承だ。

確認クイズ

Q1. クラスとインスタンスの関係として正しいのは？

正解！ クラスは1回書く形。インスタンスはいくつでも作れ、それぞれ自分のフィールドの値を持つ。

Q2. コンストラクタについて正しいのは？

正解！ クラスと同じ名前で書く準備用のメソッド。new のかっこの中の値が渡される。

Q3. Dog d1 = new Dog("ポチ", 3); Dog d2 = new Dog("ハチ", 5); のあと d2.bark() を呼ぶと？

正解！ メソッドは呼ばれたインスタンス自身（this）のフィールドを使う。d2 の name はハチ。
