カプセル化

アクセス修飾子で守る
🎯 ミッション
カプセル化の目的と、4つのアクセス修飾子がどこから触れられるかを説明できるようになろう。16マスの表を全部正しく埋め、確認クイズに全問正解すれば合格。

ねこ博士
STAGE1 の2つ目の問題を覚えているかな。体重にマイナスが入ったら、えさの量もマイナスになった。体重を書き込む場所がプログラムのあちこちにあると、どこで入ったか分からない。
うさ美
体重を書き換えるときに、毎回マイナスでないか確かめればいいですけど、書き換える場所が100か所あったら、100か所に確かめを書くことになります。1か所でも忘れたら……。
ねこ博士
STAGE1 のコピーと同じ形の問題だね。そこで、体重のフィールドを外から直接触れないようにしておいて、書き換えたいときは、確かめを1か所に書いたメソッドを通してもらう。
class Animal {
    private double weight;            // 外から直接は触れない
    public double getWeight() { return weight; }
    public void setWeight(double w) {
        if (w <= 0) throw new IllegalArgumentException("体重は0より大きく");
        weight = w;                   // 確かめてから書き換える
    }
}
 throw は「ここでおかしな値を見つけた」と知らせて処理を止める書き方
ねこ博士
データを中に閉じ込めて、決まった入口からだけ触れるようにすることをカプセル化と呼ぶ。薬のカプセルのように、中身を外から守るんだ。どこから触れてよいかを決める印をアクセス修飾子と呼び、Java には4段階ある。
private：そのクラスの中だけ 何も付けない：同じパッケージ（同じフォルダのようなまとまり）のクラスまで protected：同じパッケージ ＋ 別のパッケージの子クラス public：どこからでも
うさ美
パッケージというのは？
ねこ博士
関係の深いクラスをまとめたグループのことだ。たとえば、動物のクラスは zoo.animals、飼育係のクラスは zoo.staff、というようにまとめる。大きなプログラムでは、クラスが何千個にもなるから、グループに分けて名前がぶつからないようにしているんだ。
うさ美
private から public に向かって、触れる場所が広がっていくんですね。private は自分だけ、public はだれでも。protected は「家族（子クラス）と近所（同じパッケージ）」まで。
ねこ博士
そう。迷ったら、できるだけ狭くしておくのが基本だ。外から触れる場所が少ないほど、「この値はどこで変えられたのか」を調べる範囲が狭くなるし、中の作りを変えたいときも、外に影響を与えずに変えられる。
うさ美
全部のフィールドに getWeight() と setWeight() を作るのは、手間がかかりませんか？
ねこ博士
いい質問だね。何も考えずに全部のフィールドに set を作ると、結局だれでも何でも書き換えられるので、private にした意味が薄れてしまう。大事なのは、正しい値だけが入るように入口を設計することだ。体重のように確かめが要るものには確かめ付きの入口を、作ったあとに変える必要がないものには入口を作らない、というようにね。

確認クイズ

Q1. カプセル化の目的として正しいのは？

正解！ 正しさを守る確かめを1か所に集められる。値がおかしくなったとき、調べる範囲も狭くなる。

Q2. protected のフィールドに触れられないのは、どこから？

正解！ protected は、同じパッケージと子クラスまで。関係のない外のクラスからは触れない。

Q3. アクセス修飾子を選ぶときの基本は？

正解！ 触れる場所が少ないほど、まちがいの原因を探しやすく、中の作りも変えやすい。
