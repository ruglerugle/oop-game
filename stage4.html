抽象クラスとオーバーライド

中身は子クラスが書く
🎯 ミッション
抽象クラス・抽象メソッド・オーバーライドの意味を説明できるようになろう。3つの動物の speak() を書き直して全員に呼び、確認クイズに全問正解すれば合格。
未達成
ねこ博士
動物はみんな鳴く。だから「鳴く」という speak() メソッドを Animal に書きたい。でも、Animal の speak() の中身には、何と書けばいいかな。
うさ美
犬ならワン、猫ならニャー、鳥ならピヨ……。「動物」としての鳴き声は決められません。
ねこ博士
そう。こういうときは、親クラスには「speak() というメソッドがある」という名前と形だけを書き、中身は書かない。これを抽象メソッドと呼び、abstract を付ける。抽象メソッドを持つクラスは、それ自体も abstract class と書く。
abstract class Animal {
    String name;
    abstract String speak();   // 中身なし。子クラスが必ず書く
}
class Dog extends Animal {
    @Override
    String speak() { return "ワン"; }   // 親のメソッドを書き直す
}
 String speak() は「文字の並びを答えとして返す」メソッド。return でその答えを返す
ねこ博士
子クラスで、親と同じ名前・同じ形のメソッドを書き直すことをオーバーライド（上書き）と呼ぶ。@Override は「親のメソッドを書き直すつもりです」という印で、書かなくても動くけれど、付けておくと、名前をまちがえて書き直したつもりになっていないかをコンパイラが確かめてくれる。
うさ美
抽象メソッドを持つ Animal で、new Animal() としたらどうなりますか？
ねこ博士
コンパイラが止める。もし作れてしまったら、そのインスタンスに speak() を呼んだとき、実行する中身がどこにも無いからね。抽象クラスは「子クラスの共通の形」を決めるためだけのクラスで、それ自体から実物は作れない。
うさ美
逆に、Animal を継承した子クラスは、speak() を書かないと……そのクラスも中身の無いメソッドを抱えたままなので、new できない。だから、子クラスを作る人は、speak() を書き忘れることがないんですね。
ねこ博士
そう。「書き忘れたらコンパイラが教えてくれる」という約束になっている。これは、STAGE1 で困っていた「直し漏れ」と同じ種類の事故を、仕組みで防いでいるんだ。
うさ美
抽象メソッドではない、ふつうのメソッドもオーバーライドできますか？ たとえば Animal の eat() を、Bird だけ「種をついばむ」に変えたいときは。
ねこ博士
できる。親で中身を書いてあるメソッドでも、子で書き直せば、子のインスタンスでは子の中身が使われる。STAGE3 の「自分 → 親の順に探す」決まりを思い出すと、自分のクラスで先に見つかるからだね。親の中身も使いたいときは、super.eat() と書けば、親の eat() を呼べる。
抽象メソッド（abstract）：名前と形だけを親が決め、中身は子が必ず書く 抽象クラス：抽象メソッドを持つクラス。new できない。共通の形を決める役 オーバーライド：子が親のメソッドを同じ形で書き直す。@Override で確かめてもらえる。親の中身は super.メソッド() で呼べる
うさ美
同じ speak() なのに、犬はワン、猫はニャー。呼ぶ側は、相手が犬か猫かを気にしないといけないんですか？
ねこ博士
そこが次のステージの主題だ。答えは「気にしなくていい」。

確認クイズ

Q1. 抽象メソッドの説明として正しいのは？

正解！ abstract を付けた中身の無いメソッド。子クラスがオーバーライドして中身を書く。

Q2. 抽象クラス Animal について、new Animal() ができない理由は？

正解！ 抽象クラスは共通の形を決める役。実物は、中身を全部書いた子クラスから作る。

Q3. @Override を付ける主な理由は？

正解！ 付けなくても動くが、spek() のように書きまちがえて新しいメソッドを作ってしまう事故を防げる。
