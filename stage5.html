STAGE 5

ポリモーフィズム

同じ呼び方で、違う動き
🎯 ミッション
ポリモーフィズム（同じ呼び方で中身ごとに違う動き）と、キャストを安全に使う方法を説明できるようになろう。動物の配列で3種類の呼び方を試し、確認クイズに全問正解すれば合格。
未達成
ねこ博士
犬は動物の一種だった（is-a）。だから Java では、Animal 型の変数に Dog のインスタンスを入れられる。Animal a = new Dog("ポチ"); という書き方ができるんだ。
うさ美
変数の型は Animal なのに、入っているのは Dog。どちらとして扱われるんですか？
ねこ博士
2つを分けて考えるといい。変数の型（Animal）は、「この変数に対して、どんなメソッドを呼んでよいか」をコンパイラが確かめるためのもの。中身のクラス（Dog）は、「実際にどの中身が動くか」を決める。だから a.speak() は、Animal に speak() があるので呼んでよく、動くのは Dog の speak()、つまり「ワン」だ。
Animal a = new Dog("ポチ");　変数の型：Animal　／　中身のクラス：Dog 呼んでよいか → 変数の型で判断（Animal にある speak() は呼べる。Dog だけの fetch() は呼べない） どの中身が動くか → 中身のクラスで決まる（Dog の speak()）
ねこ博士
では、Animal 型の配列 Animal[] zoo に、犬・猫・鳥のインスタンスを入れて、for (Animal a : zoo) a.speak();（zoo の中身を1つずつ a に入れて speak を呼ぶ）としたら、何が表示されるかな。
うさ美
変数 a の型はどれも Animal だけど、動くのは中身のクラスの speak() だから……ワン、ニャー、ピヨ、とそれぞれの鳴き声が出る、ということですか？
ねこ博士
そう。同じ呼び方で、中身ごとに違う動きをすることをポリモーフィズム（多様な形を持つこと、多態性）と呼ぶ。新しくウサギのクラスを足しても、全員を鳴かせるコードは1文字も直さなくていい。STAGE1 の「変更に強い」の、いちばん大きな成果がこれだ。
うさ美
Dog だけの fetch()（ボールを取ってくる）を呼びたいときは？ 変数の型が Animal だと呼べないんですよね。
ねこ博士
変数の型を Dog に変える必要がある。Dog d = (Dog) a; のように、かっこで型を書いて変換することをキャストと呼ぶ。ただし、これは「中身は Dog のはずだ」という、書く人の思い込みをコンパイラに伝えているだけだ。中身が本当に Dog かどうかは、実行してみるまで分からない。
うさ美
中身が Cat だったら……Cat を Dog として扱うことはできないので、実行中にエラーになる。
ねこ博士
そう。Java は ClassCastException というエラーを出して止まる。だから、キャストの前に instanceof で中身を確かめる。if (a instanceof Dog d) と書けば、「a の中身が Dog なら、Dog 型の変数 d に入れて使う」という意味になる（Java 16 からの書き方）。
キャスト (Dog) a：変数の型を変える。中身が違えば実行中に ClassCastException 安全な書き方：if (a instanceof Dog d) { d.fetch(); }　中身を確かめてから使う
うさ美
でも、instanceof で種類ごとに分けて書き始めると、STAGE1 と同じで、動物が増えるたびに直す場所が増えませんか？
ねこ博士
大事なところに気づいたね。instanceof を何度も並べたくなったら、設計を見直す合図だ。種類ごとに違う動きなら、まずはオーバーライドで、それぞれのクラスに書いてもらう。instanceof は、どうしても特定の種類だけの機能を使うときの最後の手段なんだ。

確認クイズ

Q1. Animal a = new Cat("タマ"); a.speak(); で動くのは？

正解！ 呼んでよいかは変数の型（Animal）で確かめ、動く中身は中身のクラス（Cat）で決まる。

Q2. ポリモーフィズムの良いところは？

正解！ a.speak() の1行が、犬にも猫にも、あとから足したウサギにも使える。

Q3. Dog d = (Dog) a; が実行中にエラー（ClassCastException）になるのは？

正解！ キャストは「中身は Dog のはず」という思い込み。違えば実行中に止まる。instanceof で確かめてから使う。
