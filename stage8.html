STAGE 8

static

クラスに1つの値
🎯 ミッション
static フィールド・static メソッドが、インスタンスのものとどう違うかを説明できるようになろう。犬と猫を合わせて3匹作って数の変わり方を確かめ、確認クイズに全問正解すれば合格。
未達成
ねこ博士
動物園に、これまでに何匹の動物が来たかを数えたい。Animal に int count; というフィールドを作って、コンストラクタで1増やせばいいだろうか。
うさ美
フィールドはインスタンスごとに別々だから……ポチの count、タマの count、とそれぞれが自分の count を持つ。どれも、自分が作られたときに1増えるだけなので、全員 1 のままです。数えたいのは動物園全体の数なのに。
ねこ博士
そう。全員で1つだけ持ちたい値には、static を付ける。static を付けたフィールドは、インスタンスではなくクラスに1つだけある。
class Animal {
    static int count = 0;    // Animal クラスに1つだけ
    String name;             // インスタンスごと
    Animal(String name) {
        this.name = name;
        count++;             // だれが作られても、同じ count が増える
    }
}
class Dog extends Animal { Dog(String n) { super(n); } }
class Cat extends Animal { Cat(String n) { super(n); } }
 super(n) は親クラス Animal のコンストラクタを呼ぶ。だから Dog を作っても Cat を作っても count が増える
うさ美
static のフィールドを読むときは、どう書くんですか？
ねこ博士
クラスの名前を付けて Animal.count と書く。インスタンスが1つも無くても読める。メソッドにも static を付けられて、Math.max(3, 5)（大きいほうを返す）のように、インスタンスを作らずにクラス名で呼べる。インスタンスのデータを使わない、道具のような処理に向いている。
うさ美
static メソッドの中で、name を使うことはできますか？
ねこ博士
できない。static メソッドはインスタンスなしで呼ばれるから、「どのインスタンスの name か」が決まらないんだ。this も使えない。逆に、ふつうのメソッドからは static のフィールドを使える。
インスタンスのフィールド：new するたびに1組できる。d1.name static フィールド：クラスに1つだけ。全インスタンスで共有。Animal.count static メソッド：インスタンスなしで クラス名.メソッド() で呼ぶ。中で this やインスタンスのフィールドは使えない
うさ美
だったら、何でも static にしておけば、どこからでも使えて便利なのでは？
ねこ博士
そこには落とし穴がある。static のフィールドは、プログラムのどこからでも書き換えられる「みんなの共有物」になりがちだ。STAGE7 で「触れる場所はできるだけ狭く」と言ったね。共有物が増えるほど、「だれが変えたのか」が追えなくなる。それに、テストのときに前の状態が残ってしまうこともある。static は、本当にクラスに1つでいいもの（数の合計、決まった定数など）に限って使うのがいい。決まった定数には、変えられないように static final を付ける（例：static final double PI = 3.14159;）。

確認クイズ

Q1. static int count; と、ふつうの int count; の違いは？

正解！ 動物園全体の数のような共有の値は static。名前のようにインスタンスごとに違う値はふつうのフィールド。

Q2. static メソッドの中で、インスタンスのフィールド name を使えない理由は？

正解！ static メソッドはクラスに属し、this が無い。インスタンスのデータは、インスタンスを受け取らない限り使えない。

Q3. 何でも static にしない方がよい理由は？

正解！ 共有のものは、見えない場所から変わる。本当にクラスに1つでいいもの、変えない定数（static final）に限って使う。
